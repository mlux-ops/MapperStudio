# MadMapper 6.1.8 — Materials, FX and the ISF dialect

Sources: the shipped shader corpus (`Resources\Materials`, `LaserMaterials`, `FactoryGenerators`, `FactorySurface*FX` — ~2,500 INPUT declarations), plus decompiled `FUN_1406cd780` (ISF header parser) and `FUN_140793650` (material GPU-program builder) in `decompiled\batch1`. Counts are occurrences across the shipped `.fs` files.

## File layout of a material / FX / generator folder

```
<Name>/
  <Name>.fs          required — GLSL fragment source with the ISF JSON header in a leading /*{ … }*/ comment
  <Name>.vs          optional — vertex stage; default "Shaders/Materials/Default.vs"
  .info              <info><author/><date/></info>
  thumbnail.jpg|jpeg|png
```

Loading (`MMMaterial` constructor `FUN_141198170`, batch 4): the URL `/materials/<Name>` (or `/laser_materials/<Name>`, MadLaser only) is resolved under the library root, then the workspace root; missing folder → "Error creating material, folder doesn't exist". A `QDirIterator` with `*.fs`/`*.vs` filters (case-sensitive) requires exactly one `.fs` ("No fragment shader file in folder" / "Multiple fragment shader files in folder") and at most one `.vs` ("Multiple vertex shader files"); a missing `.vs` falls back to `Shaders/Materials/Default.vs` (or `Shaders/Laser Materials/Default.vs`). `Shaders/Materials/MacroForFixtures.vs` is loaded once globally. The folder is registered with a file watcher singleton (hot reload of edited shaders is the documented behaviour). Each material gets built-in attributes `Restart`, `Render To Texture`, `Pixel Format` (enum, default `PF_U8_BGRA`), `Requires Last Frame`, `Requires Last Frame MipMapping`. Max texture size 16384 (reported as "%1x%1" warnings on oversize media). The resource-library scan (`FUN_141254fb0`) separately reads `.info` and `thumbnail.{jpg,jpeg,png}` and caches by newest mtime. `FUN_140793650` builds the `MaterialGPUProgram` with six stage slots (vertex, fragment, tess-control, tess-eval, geometry, compute — the last four unused).

Drag-and-drop import (`FUN_141436140`) sniffs a dropped `.fs`/folder for `materialColorForPixel` or `laserMaterialFunc` and asks the user to import it into the project folder first. The new-material template (`FUN_14127f010`) is:

```glsl
vec4 materialColorForPixel(vec2 texCoord)
{
   return vec4(1.0, 1.0, 1.0, 1.0);
}
```

Entry points: materials implement `vec4 materialColorForPixel(vec2 texCoord)`; laser materials `laserMaterialFunc(...)` (or `void vectorMaterialFunc`, which the include wrapper tags with `#define LASER_MATERIAL_V1`); Surface FX implement `fxColorForPixel(vec2 mm_FragNormCoord)` (+ optional `fxVsFunc`). Fixture rendering uses its own shader (`FUN_1413807c0`, with `mm_PixelDataTex` / `mm_RequiresPixelDataTex`). `#include "<path>"` lines are generated by the preprocessor wrappers (`FUN_1407944e0`, `FUN_140794930`, `FUN_140794ed0`); the resolver (`FUN_1405fe1e0`) reports "Incomplete "#include" directive" / "Included file not found". `MadNoise.glsl` and `MadSDF.glsl` are the shipped include libraries (see `05-guides-digest.md`). `#line` bookkeeping is in `FUN_1406cc9c0`.

## Shader assembly (`FUN_1407a54f0` preamble, `FUN_1407b11a0` stage assembly)

Preamble, in order (each `uniform` is emitted only when its token occurs in any stage source, except where marked):

```glsl
// Globals
uniform float TIME;            // if "TIME" occurs (also matched by CLOCK_TIME/TIMEDELTA)
uniform float CLOCK_TIME;
uniform vec4 DATE;
uniform float TIMEDELTA;
uniform float FRAMEINDEX;
uniform int PASSINDEX=0;       // always
uniform vec2 RENDERSIZE;       // always
uniform int MOUSEKEYSTATE;     // together with MOUSEPOS when either occurs
uniform vec2 MOUSEPOS;

// Macros
#define IMG_SIZE(s) s##_size
#define IMG_NORM_PIXEL(s, location) texture(s,(location)*s##_mult+s##_add)
#define IMG_PIXEL(s, location) IMG_NORM_PIXEL(s, vec2(0,1) + vec2(1,-1) * (location) / RENDERSIZE)
#define IMG_THIS_NORM_PIXEL(s) IMG_NORM_PIXEL(s, isf_FragNormCoord)
#define IMG_THIS_PIXEL(s) IMG_PIXEL(s,gl_FragCoord.xy)
#define IMG_NORM_PIXEL_LOD(s, location, lod) textureLod(s,(location)*s##_mult+s##_add,lod)
#define IMG_TEXEL_FETCH(s, location, lod) texelFetch(s, ivec2(location), lod)

// Inputs
uniform bool  <name> = true|false;
uniform int   <name> = N;            // int, long
uniform float <name> = V;            // (a second float path emits "uniform highp float")
uniform vec2|vec3|vec4 <name> = vecN(...);
uniform vec4  <name> = vec4(r,g,b,a); // color
uniform mat4  <name>;
#ifdef IS_RECTANGLE_
   uniform sampler2DRect <name>;
#else
   uniform sampler2D <name>;
#endif
uniform vec2  <name>_size=vec2(1920,1080);   // image; cube → samplerCube + vec2 size, 3D → sampler3D + vec3 size (32,32,32)
uniform ivec2 <name>_mult=ivec2(1,1);
uniform vec2  <name>_add=vec2(0,0);

// Generated Attributes
uniform float <generator name> = 0.0;        // value computed on the CPU each frame

// Imported Textures
uniform sampler2D <name>; uniform vec2 <name>_size; const ivec2 <name>_mult=ivec2(1,1); const vec2 <name>_add=vec2(0,0);
```

Stage assembly: `#version <V>` (from `FUN_1407a52d0`; the guides say 150 core by default, up to 4.5 on Windows), `#define <entry>` lines, the preamble, then for the **vertex** stage — only if the source uses `isf_vertShaderInit` — the built-in block

```glsl
in vec4 mad_Position;
in vec4 mad_TexCoord0;
out vec2 isf_FragNormCoord;
void isf_vertShaderInit() {
    gl_Position = mad_Position;
    isf_FragNormCoord = mad_TexCoord0.xy;
}
```

and for the **fragment** stage `in vec2 isf_FragNormCoord;` plus `out vec4 FragColor;` when `gl_FragColor` was rewritten. Legacy rewrites applied to sources: `vv_vertShaderInit`→`isf_vertShaderInit`, `vv_FragNormCoord`→`isf_FragNormCoord`, `texture2D`/`textureCube`/`textureRect`→`texture`, `varying `→`in ` (fragment), `gl_FragColor`→`FragColor`. The `main()` wrapper around `materialColorForPixel` lives in the program builder (`FUN_140793650` path), not in these functions.

## Header grammar as implemented (`FUN_1406cd780`)

| key | handling |
|---|---|
| `INPUTS`, `PARAMETERS`, `OUTPUTS` | arrays of objects, one shared loop; `INPUTS` flags the element 0x100000, `OUTPUTS` 0x200000\|0x400 |
| `GENERATORS` | array of objects → generator parser `FUN_1406cbe30` |
| `CATEGORIES` | array |
| `DESCRIPTION`, `CREDIT` | strings → metadata `description`, `credit` |
| `VSN` (fallback `VERSION`) | string → `version` |
| `TAGS` | string only (an array is ignored) |
| `MADMAPPER_MIN_VERSION` | copied to `min_madmapper_version` ("Min MadMapper Version") |
| `MM_INTERNAL` | per element; when true the name-registration hook is skipped |
| Non-array / non-object values | silently treated as empty |
| Invalid JSON | throw "ISF directive is not valid JSon : …" |

Header keys handled by other functions (`FUN_1407ae7f0`, `FUN_1407ac740`, `FUN_1407a8c80`, `FUN_1407a2200`): `GLSL_VERSION`, `ASPECT_RATIO`, `RENDER_SETTINGS`, `RASTERISATION_SETTINGS`, `REQUIRES_TEXTURE`, `IMPORTED` (`PATH`, `GL_TEXTURE_MIN_FILTER`, `GL_TEXTURE_MAG_FILTER`, `GL_TEXTURE_WRAP`), `PASSES`, `INSTANCE_COUNT` (integer or the name of an INPUT), `POINT_COUNT`, `INDEX_COUNT`, `DEFAULT_WIDTH`, `DEFAULT_HEIGHT`, `DEFAULT_PIXEL_FORMAT`, `DEFAULT_RENDER_TO_TEXTURE`, `REQUIRES_LAST_FRAME`, `PRESERVE_ORDER`, `ENABLE_FRAME_BLENDING`, `CLAMP_MATERIAL_OUTPUT`. Multi-pass ISF is not supported per the docs; `PASSES` is parsed but limited.

## INPUT declarations (`FUN_1406c6980`, batch 4)

Keys read: `TYPE` (required non-empty string), `NAME`, `Label` then `LABEL` (first non-empty wins; `/` builds parameter groups, e.g. `Color/Brightness`), `DESCRIPTION`, `FLAGS` (string or array of strings), `ORDER_INDEX` (int, default −1), `DEFAULT`, `MIN`, `MAX`, `VALUES`, `LABELS`, `DISPLAY_X_RANGE`/`DISPLAY_Y_RANGE`, `DISPLAY_X_CURVE`/`DISPLAY_Y_CURVE`, `INTERPOLATION`, `META` (object of extra metadata), `MM_INTERNAL`, and for images `GL_TEXTURE_MAG_FILTER`, `GL_TEXTURE_MIN_FILTER`, `GL_TEXTURE_WRAP`.

| `TYPE` | DEFAULT | MIN / MAX | notes |
|---|---|---|---|
| `float` / `double` | number, default 0 | default ±FLT_MAX / ±DBL_MAX; default must lie inside | `uniform float` |
| `int` | number, default 0 | default INT_MIN / INT_MAX, range-checked | `uniform int` |
| `bool` | JSON bool, number (>0), or "true"/"false"/"" | ignored | `uniform bool`; flag `button` makes a momentary button |
| `event` | not read (false) | — | same object as bool, flags 0x1008 |
| `string` / `string_vector` | string / array of strings | — | |
| `float_vector` / `int_vector` | flat array of numbers | — | |
| `curve` | array of numbers | — | plus `DISPLAY_X/Y_RANGE` (2 values, min ≤ max), `DISPLAY_X/Y_CURVE`, `INTERPOLATION` ∈ none/linear/hermite/catmull_rom |
| `color` | **required**, 3 or 4 numbers | none | `uniform vec4`; flag `no_alpha` |
| `floatRange` | 2 numbers (0,0) | default 0 / 1, both components range-checked | range slider |
| `point2D` / `vec2` / `ivec2` | 2 numbers (0,0) | arrays of 2, both or neither | `uniform vec2` (ivec2 emission unresolved) |
| `point3D` / `point4D` | 3 / 4 numbers | arrays of same size, both or neither | `uniform vec3` / `vec4` |
| `long` | **required**, string or number | — | `VALUES` required non-empty; `LABELS` optional (defaults to VALUES); emitted as `uniform int`; flag `generate_as_define` turns options into `#define`s |
| `image` / `imageCube` / `image3D` / `usampler2D` / `polylines` | optional string | — | sampler + `_size`, `_mult`, `_add` uniforms; optional GL filter/wrap keys |
| `mat4`, `array` | — | — | `uniform mat4` |
| `audio` / `audioFFT` | — | — | delegated; only allowed in a GpuProgram-level ISF directive; `SIZE` ≤ 512 per the guide |

`FLAGS`: `button`, `button_grid`, `no_alpha`, `generate_as_define` (OR'd together; non-string entries throw "FLAGS should be an array of strings").

Validation messages (verbatim, including the typos shipped in the binary): "TYPE not defined for ISF INPUT <name>", "Error in ISF INPUT <name>: default value in not in range MIN-MAX", "…: default keys should all be strings|numbers", "…: curve DISPLAY_X_RANGE is invalid (min>max)", "…: curve DISPLAY_X_RANGE value must have two values", "…: default value for a color input must be an array of 3 or 4 value (rgb or rgba)", "…: point2D default value must have two values", "…: <TYPE> default|MIN|MAX value must have two values", "…: point3D … three values", "…: point4D … four values", "…: if <TYPE> has MIN or MAX, it must have both", "Error in ISF INPUT <name> default value of "long" input is undefined or invalid", "Error in ISF Header INPUT <name>: VALUES and LABELS arrays must have same size", "…: VALUES array is missing", "…: LABELS|VALUES entry of "long" input is invalid", "Errpr in ISF INPUT <name>: bool attribute default value is invalid", "Error in ISF input <name>: Unhandled ISF input type "<TYPE>"", "Error parsing ISF meta data <key>: no value". Name identifier/uniqueness checks (`FUN_1406c2cd0`) and label slash rules (`FUN_1406c2bd0`) run in the callee.

## GENERATORS (MadMapper extension to ISF)

A generator declares a derived uniform computed on the CPU each frame from other inputs:

```json
"GENERATORS": [
  { "NAME": "animation_time", "TYPE": "time_base",
    "PARAMS": { "speed": "speed", "reverse": "reverse", "link_speed_to_global_bpm": true } }
]
```

`TYPE` is looked up in a generator registry (`FUN_140630470`); unknown → "Unknown generator type: …". Types: `time_base` (287 uses), `animator` (32), `multiplier` (22), `incrementer`, `adsr`, `audio`, `transition_damper`, `damper_array`, `linear_filter`, `pass_thru`, `shaper`, `ease_filter`; the Materials guide also documents `damper` (hardness 0.1, damping 0.8). RTTI shows `TimeBaseGenerator` and `AnimationGenerator`.

Every `PARAMS` key must exist on the generator's parameter table ("Object of type <TYPE> has no parameter <key>"). A value is either a literal of the parameter's type (bool; number; enum string) **or a string naming another input / generated value / channel**, which binds the parameter to it — that's how `"speed": "speed"` links the time base to the `speed` slider. Wrong kinds throw "Error parsing generated <NAME>: parameter <key> should be a boolean or a string (if the parameter should be controlled by another input/generated/channel)" (or "…a number or a string…", "…a string."). The generator is exposed to GLSL as `uniform float <NAME> = 0.0;` and evaluated on the CPU each frame.

`PARAMS` keys seen in the corpus: `speed`, `link_speed_to_global_bpm`, `speed_curve`, `reverse`, `bpm_sync`, `strob` (time_base per the guide); `shape`, `max_value`, `reset`, `active`, `release`, `attack`, `decay`, `increment`, `decrement`, `input_value` (animator / adsr / incrementer / multiplier — per-type tables in batch 6).

## Header-level keys (`FUN_1407ae7f0`, `FUN_1407ac740`, `FUN_1407aade0`)

| key | rule |
|---|---|
| `GLSL_VERSION` | string, else "GLSL_VERSION must be a string"; app default `"150 core"` (setting `glsl_version`) |
| `ASPECT_RATIO` | `[num, den]` or a number, else error |
| `MEDIA` | object: fixed input `inputImage`; `GL_TEXTURE_MAG_FILTER`/`MIN_FILTER` (default `LINEAR`), `GL_TEXTURE_WRAP` (default `CLAMP_TO_EDGE`), `REQUIRES_TEXTURE` (bool, else error) |
| `PASSES` | array of `{TARGET, WIDTH, HEIGHT, FLOAT, PERSISTENT}` |
| `PERSISTENT_BUFFERS` | array of strings |
| `IMPORTED` | `{NAME: {PATH, GL_TEXTURE_*}}` |

`RENDER_SETTINGS` (object; unknown keys → "Unhandled key in ISF header RENDER_SETTINGS"):

| key | value |
|---|---|
| `INSTANCE_COUNT`, `POINT_COUNT`, `INDEX_COUNT` | integer, **or a string naming an INPUT** (so a slider can drive instancing / point count); "found in multiple files" if repeated across included files |
| `DEPTH_TESTING` | enum string (READ_WRITE … ; exact list unresolved) |
| `DEPTH_FUNC` | GL compare name: NEVER, LESS, LEQUAL, GREATER, GEQUAL, EQUAL, NOTEQUAL, ALWAYS |
| `BLEND_EQUATION` | FUNC_ADD, SUBTRACT, REVERSE_SUBTRACT, MIN, MAX (first/last unverified) |
| `BLEND_SRC`, `BLEND_DST` | ZERO, ONE, SRC_ALPHA, ONE_MINUS_SRC_ALPHA, SRC_COLOR, ONE_MINUS_SRC_COLOR, DST_ALPHA, ONE_MINUS_DST_ALPHA, DST_COLOR, ONE_MINUS_DST_COLOR |
| `CLAMP_MATERIAL_OUTPUT` | bool → attribute "Clamp Material Output (in range 0.0 - 1.0)" |
| `TREAT_AS_ILDA_FRAME` | bool → "Treat Material output as RAW ILDA frame" (laser) |
| culling | FACE_BACK / FACE_FRONT / FACE_BACK_FRONT literals exist; key name unresolved |

Invalid enum values raise "Invalid value for <KEY>: <v> (possible values are …)".

`RASTERISATION_SETTINGS` (object; only these keys, others → "Unhandled key …"):

| key | value |
|---|---|
| `DEFAULT_RENDER_TO_TEXTURE` | bool ("Material Rasterization Default Mode") |
| `DEFAULT_WIDTH`, `DEFAULT_HEIGHT` | integer 1…32768 |
| `DEFAULT_PIXEL_FORMAT` | pixel-format enum string (e.g. `PF_U8_BGRA`) |
| `REQUIRES_LAST_FRAME` | bool → adds the `mm_LastFrame` sampler input ("Last Frame") |
| `REQUIRES_LAST_FRAME_MIPMAPPING` | bool |

Laser-material render settings documented in the Laser Materials guide (`MAX_SPEED`, `SKIP_BLACK`, `PRESERVE_ORDER`, `ANGLE_*`, `*_POINT_REPEAT`, `POLY_FADE_IN`, `MIN_ILDA_POINTS_PER_POLYLINE`) are handled by the laser program path, not these two parsers.

## Generator registry (`FUN_140630470`)

`damper` → DamperFilter · `transition_damper` → TransitionDamperFilter · `damper_array` → DamperFilterArray · `adsr` · `animator` → AnimationGenerator · `incrementer` → IncrementerFilter · `linear_filter` · `pass_thru` · `time_base` → TimeBaseGenerator · `shaper` · `ease_filter` · `multiplier`. Anything else → "Unknown generator type". (`audio`/`audioFFT` are input types, not generators.) Each class builds its parameter table in a separate function (`FUN_14061dca0` time_base, `FUN_14061b730` animator, `FUN_14061ca20` incrementer, `FUN_14061e020` transition_damper) that was not decompiled; the guide-documented parameters are: time_base `speed`, `reverse`, `speed_curve`, `strob`, `bpm_sync` (+ `link_speed_to_global_bpm` in the corpus); damper `hardness` 0.1, `damping` 0.8; adsr `attack`, `decay`, `release`; incrementer `increment`, `decrement`, `reset`, `max_value`; animator `shape`, `active`; pass_thru / multiplier `input_value`.

## `#include` (`FUN_1405fe1e0`)

`#include "<path>"` is split on whitespace then on `"`; malformed → "Incomplete "#include" directive in file …", missing → "Included file not found in file …". The same preprocessor serves Lua (`-- ` comments) and Python (`# `) sources. Resolution base directories (shader library `Shaders/`, the material folder, the workspace) are chosen by the caller.

## Fixture (LED) shader (`FUN_1413807c0`)

LED fixtures are rendered by a dedicated 8 KB GLSL program (full text saved as `index\fixture_shader.glsl`): `#version 150 core`; uniforms `mm_FixtureTex`, `mm_PixelMappingTex`/`mm_RequiresPixelMappingTex`, `mm_PixelDataTex`/`mm_RequiresPixelDataTex`, `mm_FixtureWidth`, `mm_FixtureHeight`, `mm_PixelSize`, `mm_Dir`, `mm_OversamplingWidth/Height`, `mm_ResponsePower`, `time`, `mm_TextureMatrix`, `mm_ModulationColor`, `mm_Highlight`, `mm_IsCircle`, `mm_CircleThickness`, `mm_CircleArc`, one `mm_Slider_N` per fixture slider; `in vec2 texCoord1; out vec4 mm_out_color;`; an `mm_averagePixel` oversampling helper and one branch per pixel component count. `mm_PixelDataTex` is a one-row texture with two texels per LED: texel 2i = pixel centre in fixture UV, texel 2i+1 = local X axis (.xy) and Y axis (.zw) for the oversampling kernel; without it the centre is derived from the fixture grid.

## Legacy handling

Library folders `Gradient Color_Legacy3`, `Line Patterns_Legacy3`, `Shapes_Legacy3` exist; the binary carries `_Legacy3` (near "Relinked materials") and `_Legacy4` (stripped from generator module names in the visuals loader). So renamed materials keep an old copy so older projects relink.
